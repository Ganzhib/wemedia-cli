- 仍未对长期发布成功率作 95% 保证；搜索条数、跨网络多轮表现和平台审核耗时继续按下文跟踪。

## 卡点与优化顺序

1. **P1：搜索条数不符合 `--limit`。** `article search TypeScript --limit 2 --json` 返回 20 条。先核对搜索接口接受的分页字段，再修正请求与游标；不能只在客户端截断，否则下一页会跳过其余结果。修复后用真实接口验证 2 条和连续分页。
2. **P1：提交后的状态不够明确。** 发布文章和创建专栏均返回 `submitted`，立即读取详情得到 404。CLI 应在结果中说明审核状态，并提供按 ID 查询提交状态或“等待公开可见”的命令；自动化不应把详情 404 当作写入失败并重放写请求。
3. **P1：首次浏览器安装缺少进度。** `auth setup --json` 在下载期间长时间没有输出。保持 JSON 的单文档约束，在 stderr 提供可选进度，或在交互模式显示进度与预计操作；同时报告缓存命中。
4. **P2：列表响应过大。** `column list --limit 2 --json` 包含冗长的作者资料。提供摘要视图或 `--fields`，同时保留获取完整详情的路径，减少 Agent 处理和用户阅读时间。
5. **P2：连续命令耗时。** 已安装 CLI 的 13 个只读检查总耗时约 28.6 秒；网络读取通常约 2–4 秒，纯本地 schema 和 history 约 0.5 秒。优先测量 HTTP 耗时并考虑安全的只读连接复用或批量查询；写请求保持不自动重试。
6. **P2：验收残留。** 真实测试会留下文章和专栏，目前 CLI 无删除命令。若平台允许，增加明确确认的清理流程；在此之前，自动化写入必须显式启用，记录已生成 ID，不能在失败后自动重跑。

## 可重复验收

当时的 `scripts/live-acceptance.mjs` 接收已安装包的 `dist/cli.js` 路径，默认只读；输出每步通过状态与耗时。显式传 `--write` 只创建或更新草稿并上传素材，不创建测试专栏或公开发布占位正文。脚本遇到写入失败立即停止，输出已取得的 ID，依靠 `juejin history --json` 核对远端状态后再决定下一步。输出字段为 `command_check_pass_rate`，公开发布结果另列 `not_tested`。

下一轮目标：先修复搜索分页，再在多轮、不同时间段和网络条件下运行无写入验收；对写入流程使用独立测试账号和可清理的内容，记录每步成功率、P50/P95 耗时以及审核完成时间。达到 95% 需要足够样本和明确的成功判定，不能从一次运行推断。

## 开发版优化与真实文章验证

- 精确标签解析找到匹配即结束，重复标签去重；公开模糊搜索保留完整分页。
- 普通模式每 5 秒给出等待提示；提交结果说明审核状态，失败展示写入回执。JSON 模式保持单文档约束。
- 增加文章模板和技术写作指南，按架构、教程、排障、经验总结选择结构；依据真实配置生成 frontmatter。
- 增加 `article publish-directory`：全量预检、同专栏顺序发布、进度保存、完成项跳过、未知写入停止。暂不包含递归目录扫描和自动处理平台审核。
- 同一模板实测：ID 配置预检 2.389 秒，精确名称预检 3.553 秒。单次样本，仅用于定位开销，不作为性能保证。
- 正式文章《从命令到工作流：juejin-cli 如何让写作自动化更可靠》经新批量入口提交，命令耗时约 5.5 秒。文章 ID `7706807603482361907`，专栏 ID `7706937894392823859`；重复执行成功跳过完成项。立即查询详情返回 404，专栏列表 count=1 但公开 items 为空，公开可见性仍待确认。
- 以上变更尚未发布到 npm；当前线上包仍为 0.1.0。搜索条数限制问题仍未修复，不宣称长期成功率已达 95%。
