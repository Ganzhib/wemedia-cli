# wm 通用核心实施计划

本计划配套 [通用发布核心设计](rfcs/0001-generic-publishing-core.md)。0.2 交付可靠的单机发布闭环；0.3 交付远端内容更新；0.4 验证新增平台。当前已实现入口收敛及第一批能力契约与账号身份，后续批次仍按下列完成条件推进。

## 交付原则

每一批改动都接入真实调用路径和现有平台，附带可观察行为的测试。领域模型与处理器在同一批贯通，不先提交只有接口或空实现的大框架。以 wm 为唯一 CLI 和 Skill 入口，不建立旧契约的自动兼容或迁移层。

已经使用的底层协议、上传器、渲染器和浏览器流程可以继续复用；仅为旧命令或旧 SDK 形状服务的封装应随切换删除。历史数据不覆盖、不自动重放；旧版本与新版本的数据不混读。

## 当前入口收敛

| 工作 | 完成条件 |
| --- | --- |
| 单一 Skill | skills/ 只含 wm 一个入口；主文件通过 schema 发现平台 |
| 安装与检查 | skill install、skill status 不再有按名称选择旧 Skill 的参数 |
| 分发与说明 | tgz、站点构建和文档均只分发 wm；平台资料是参考文件 |
| 用户文件 | 新安装器不扫描或搬迁旧目录；独立安装和自定义技能不删除 |

本批不改变平台远端写入行为。代码检查、安装保护测试和实际归档安装检查需要通过。

## 0.2 第一批 能力契约与账号身份

当前开发版本 0.2.0-alpha.1 已贯通：开放能力注册、同源输入输出 schema、独立平台选项、稳定账号绑定、共享会话代次和账号锁、真实驱动调用、通用 platform exec、单一 Skill 下的平台独立指导。旧命令树和 SDK 转接导出已删除；账号通过新登录流程建立，不读取旧布局。

验证包含 HTTP 与 Chromium 下的三个实际平台处理器、二进制内容、自定义能力和资源、别名重绑、共享锁、异常回执，以及 SDK 的编译期契约检查。模拟页面通过不代表线上写入已经验收；账号快照、跨任务操作记录和验证恢复仍属于后续批次。

修改 core/types、core/registry、runtime/accounts、CLI 注册处及三个平台定义。将封闭的平台格式与能力枚举改为注册定义，将输入校验、探测、处理器和元数据归属于同一能力。

建立 AccountBinding，计划绑定平台稳定账号 ID。同一个账号的多个别名映射到同一身份与锁。登录、验证与操作复用一次账号会话，避免重复浏览器启动。新账号布局通过登录建立，不读取旧格式建立绑定。

交付时，现有能力均通过新定义实际运行；删除被替代的旧入口与转接导出。一个自定义能力可以通过通用调用执行；没有注册的能力在远端请求前被拒绝。

## 0.2 第二批 内容快照与计划

增加内容导入器、对象存储、ContentRevision、PreparedVariant 与计划服务。修改 publishing 服务，使各平台使用不可变快照，而不是在认证后读取原始文件。

计划记录身份、输入、实际平台产物、工作流及驱动版本。preview 仍可离线运行。平台上传限制由平台校验器负责，公共资产层不继承任一平台的数量或大小规则。

交付时，移动源文件不影响已有计划；扫码期间修改原图不会改变计划上传内容；实际产物变化形成新的业务输入。临时路径和 CLI 版本不再触发发布副本。

## 0.2 第三批 操作去重与步骤记录

将跨目标循环改为调用通用工作流执行器。OperationRecord 持有步骤状态、结果、证据和远端引用；任务摘要和 Publication 索引从其派生。

为各目标的实际操作计算语义键，在锁内查找或建立操作记录。相同内容先发 A、B 再发 A、C 时，A 引用原记录。新副本的 nonce 贯穿依赖的创建步骤。

交付时，断网或崩溃后同一步骤不重发；一个目标失败保留其他结果；索引或事件写失败不会使已确认的远端效果被重新执行。并发任务不能绕过去重。

## 0.2 第四批 回查与验证恢复

为每种有写入副作用的步骤补充可用的回查证据和恢复策略。明确不具备回查能力的场景，保留 unknown，不能用标题匹配、固定等待或空列表推断可重试。

refresh 逐目标记录观察，resume 按步骤证据继续。执行状态与当前远端状态分离；过去已提交和目前已删除可以同时正确表达。验证流程在同进程保留会话，跨进程由驱动从资源引用恢复。

交付时，草稿存在不会触发重复发表，扫码超时不会伪造成功，某个平台回查失败不影响其他目标，结构化错误包含可以执行的下一步动作。

## 0.2 第五批 现有平台线上验收与发行

在指定内容与账号上分别验收草稿、发表、回读、审核状态和强制验证。每个能力关联驱动版本及证据，真实读取成功与真实写入通过分别记录。

只有取得实际证据的能力标注相应验收级别。用户侧完成安装和登录后，AI 能处理排版、上传、选封面、后台操作和结果核对。npm 发行作为独立动作进行，不因合并设计或代码 PR 自动发布。

0.2 结束条件是完整闭环及恢复通过，不以平台数量或接口数量作为完成标准。

## 0.3 远端内容管理

补齐 Publication 查询、已有草稿更新与来源修订关联。更新前读取远端版本或内容摘要；外部编辑造成冲突时给出具体差异，不覆盖用户在平台上的新内容。

上传缓存按账号、用途和内容摘要隔离，遵循平台有效期。平台预览保存真实产物并报告字段、图片顺序和正文差异。源文件保持原状。

交付时，AI 能定位并修改一份既有草稿，再从该资源继续发布；不通过重新创建相同标题的草稿来模拟更新。

## 0.4 新平台接入验证

选择有真实用户需求的平台，单独调研登录、发布、回查和开源许可，再接入现有契约。新增改动应集中在平台目录、注册项和测试。

如果接入需要修改核心中的平台名称分支或新增固定内容格式枚举，应先修正抽象边界。平台能力可以不同，但账号、计划、操作记录、恢复和 JSON 输出必须共用。

外部插件、API 驱动、定时执行和批处理随后按需求增加；它们调用同一执行器，不另建发布系统。

## 必须通过的故障场景

| 场景 | 预期 |
| --- | --- |
| 相同目标换序或两批目标部分重叠 | 已完成目标不再次写入 |
| 别名重新绑定其他账号 | 旧计划拒绝发送到新账号 |
| 原文件删除或修改 | 新计划使用新的修订，旧计划使用自己的快照 |
| 相同资产在不同账号或不同用途上传 | 不串用素材标识 |
| 远端成功后索引或事件写入失败 | 回执事实保留，可重建视图 |
| 请求超时且缺少稳定回查标识 | unknown，不自动重发 |
| 草稿保存后发表响应丢失 | 使用发表证据回查，不能仅凭草稿存在重发 |
| 用户验证超时 | 保留任务与必要引用，给出恢复动作 |
| 一个目标回查失败 | 其他目标继续返回结果 |
| 已提交内容后来删除或审核拒绝 | 保留历史提交证据，更新当前远端观察 |
| 新平台没有草稿或只接受视频产物 | 无需核心特例即可运行 |
| 用户修改 Skill 或存在独立同名 Skill | 不覆盖、不删除用户文件 |

离线测试验证明确机制，浏览器测试拦截真实写接口。线上验收只处理已经指定的内容和操作，不用测试文章污染用户账号。
