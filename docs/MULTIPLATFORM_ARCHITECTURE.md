# 多平台文章发布 CLI 架构设计

wemedia-cli 是面向开发者和 AI Agent 的多平台文章发布工具，终端命令规划为 wm。首批平台为掘金、小红书、微信公众号；后续平台通过同一适配边界接入。juejin-cli 提供可修改的实现基线，不决定公共层的数据模型和平台能力。

用户只需安装和登录。文章预览、图片上传、封面、草稿、发表与结果查询由 CLI 操作；平台强制的身份确认由用户完成。AI 通过命令与 schema 调用业务能力，不需要理解后台 DOM、寻找按钮、提取 Cookie 或指导用户逐步填表。

本文是设计目标。当前分支保留基线实现并新增调研与设计文档，以下 wm 命令、接口和目录尚未实现。开源复用证据与验证边界见 [平台调研](PLATFORM_RESEARCH.md)。

## 产品契约

首次使用流程为安装、登录、描述需求。浏览器、必要的发布引擎及其生命周期由 wm 管理。默认不要求 AppID、AppSecret、IP 白名单、Docker、独立运行 MCP 服务或手工加载扩展。开发者 API 和自托管网关作为可选驱动保留。

登录时打开受管理的浏览器或显示二维码，登录成功后核对实际创作者账号。后续业务自动处理页面。浏览器可以有界面运行，用户无需操作后台表单；全程无头运行不作为平台能力的必要条件。

平台发起验证码、管理员扫码或设备验证时，任务进入 waiting_for_verification，给出本机验证入口，验证后从当前阶段恢复。不能承诺一次登录永久有效，也不能将管理员确认当作可绕过的普通弹窗。

每个写命令返回实际完成阶段。草稿保存、发布提交、审核通过和群发成功分别记录；有结果不确定的阶段时返回可查询任务 ID，不声称操作成功。

## 分层与依赖

```text
CLI 与 Agent Skill
        ↓
应用服务：账号、内容准备、发布任务、恢复与查询
        ↓
平台能力注册表与类型契约
        ↓
platform/juejin  platform/xiaohongshu  platform/wechat
        ↓
平台驱动：HTTP、受管理浏览器或本地引擎

content：解析、资产清单、按平台渲染
runtime：账号目录、浏览器进程、引擎、锁、任务存储、诊断
```

平台实现不导入 CLI。公共 runtime 不导入任何平台协议。浏览器 runtime 提供受管理的上下文和生命周期；登录页面、账号判断、选择器及页面 fetch 属于对应平台驱动。平台特有数据只在对应适配器里解释。

首期使用单 npm 包和显式内置注册表，便于共享类型与版本。外部引擎通过薄客户端封装。新增平台不需要先建设插件市场、多个工作区包或运行任意远程插件代码。

## 平台与驱动

平台表示用户使用的产品，例如 wechat。驱动表示完成某项能力的技术路径，例如 wechat.browser、wechat.api。不同驱动使用各自认证方式，但对外属于同一个平台。

| 平台 | 默认驱动目标 | 可选驱动 | 首批业务能力 |
| --- | --- | --- | --- |
| juejin | 复用现有账号登录与 HTTP/页面传输 | 后续按实际协议调整 | 草稿、图片、文章发布、专栏 |
| xiaohongshu | CLI 管理的本地浏览器引擎 | 原生浏览器驱动，后续评估 | 图文准备、发布与回查；草稿在验证持久化后开放 |
| wechat | 受管理浏览器，文颜负责排版 | 官方 API、自托管网关 | 草稿、图片、封面与回读；正式发表通过独立验收后开放 |

能力是否可用由驱动实现、账号权限和运行时前置条件共同决定。注册表的静态声明不能代替登录后的能力探测。平台专有的合集、原创或评论等扩展保留独立命名空间，不强迫所有平台接受同样参数。

驱动在创建任务时确定并写入快照。切换驱动需要创建新计划或明确处理原任务；提交超时后不能自动改用另一条传输重发。

## 能力契约

能力以业务操作区分，例如 article.createDraft、article.updateDraft、article.publish、article.status、asset.upload、collection.list。公众号群发是 article.massSend，不与 publish 合并。

平台实现只注册真实支持的操作，没有实现的能力不提供空函数或伪造成功。每项能力包含输入类型、输入边界校验、权限要求、副作用类型和处理器。命令树、schema 与调度依据同一份定义生成，避免手写三套配置。

输入模型保留公共部分和平台配置。标题、正文、来源文件、作者、摘要与资产属于公共内容；掘金分类、专栏，小红书图集与话题，公众号原创、合集及发布方式属于平台配置。不为统一接口要求不存在的分类、专栏或草稿 ID。

媒体是一等内容类型。首期公共源是 Markdown，平台输出可以是 Markdown、富文本 HTML 或图集加短文。小红书长文、视频等由独立能力接受对应输入，不将任意 Markdown 自动删改成短笔记。

## 内容与平台渲染

内容处理按读取源文件、解析元数据、构建资产清单、应用目标配置、平台渲染、校验的顺序运行。本地准备与平台写入分开，使 preview 不会意外上传图片或创建草稿。

元数据优先级为命令参数、目标平台配置、公共 frontmatter。平台键以稳定标识命名，例如 platforms.wechat、platforms.xiaohongshu。公共解析仅校验用户输入类型，平台规则由对应 adapter 校验一次。

公共资产清单记录原始路径、媒体类型、大小和内容摘要。平台对格式、尺寸和数量的限制在各自校验器中处理，不能沿用掘金的 5 MiB 限制约束所有平台。上传后用语法树和源坐标替换真正的图片引用，源文件保留原状。

上传结果按平台、账号、资产内容摘要和上传用途缓存。同一图片在公众号正文和封面可能需要不同类型的素材标识，不能只按路径复用，也不能跨账号共享 media_id。

## 账号与浏览器生命周期

账号身份由 platform 与 accountId 共同标识。用户可以设置友好别名，但任务始终保存经过平台验证的身份。认证、Profile、上传缓存和写锁均按这个作用域隔离。

```text
~/.config/wemedia-cli/
  accounts/<platform>/<accountId>/
    account.json
    credentials/
    browser-profile/
    assets.json
    write.lock
  jobs/<jobId>/
    plan.json
    events.jsonl
    artifacts/
  engines/<engine>/<version>/<os>-<arch>/
```

凭据只由对应驱动读写，业务计划、操作回执和错误输出不包含 Cookie、Token 或密码。POSIX 下凭据文件使用 0600、目录使用 0700。外部输入与持久化文件在拥有它们的边界校验，成功的内部类型不在每层重复检查。

受管理浏览器使用独立 Profile，不接管用户日常浏览器。CLI 自动定位或准备浏览器，登录后探测业务后台；未登录、已登录但无权限、临时验证和平台维护分别报告。验证过程中保留必要的上下文；恢复到新进程时先回查已提交阶段，不能重新点击提交。

运行本地引擎时由 runtime 管理固定版本、完整性校验、访问凭据、健康检查、工作目录和退出。用户不接触端口配置或服务启动。CLI 自有账号锁约束本机任务；独立后台和其他设备仍可能并发修改，适配器在更新前读取必要版本或内容摘要。

## 发布任务与恢复

任务按内容版本、目标平台和账号划分，每个目标独立记录进度。多平台发布没有跨站事务，一个平台成功、另一个失败时返回部分完成；不为模拟回滚自动删除已发布内容。

每个阶段记录明确的副作用，例如 asset.upload、article.createDraft、article.publish。执行写入前先持久化 intent，响应后记录平台标识和证据。网络失败与明确业务拒绝分别处理。

```text
planned → prepared → running
                    ├─ waiting_for_verification → 原阶段继续或先回查
                    ├─ draft_saved
                    ├─ submitted → processing → published
                    ├─ rejected
                    └─ unknown → 只读核对 → 已确认结果或待处理
```

这些是公共展示状态，驱动可以有更细的内部阶段，不要求小红书像公众号一样先创建远程草稿。草稿标识、发布任务 ID、文章 ID 和编辑页面地址是不同类型，全部按字符串保存；平台未提供的字段不伪造。

unknown 表示写入可能已发生，禁止自动重放。resume 首先查询已经保存的远程标识与平台状态，复用已确认的素材和草稿，只执行明确尚未发生的阶段。没有稳定回查标识时保留未知，不用标题相同作为唯一判定依据。公开 API 不支持幂等时，本地指纹无法保证跨设备恰好一次。

本地去重键包括内容修订、平台、账号、动作、目标配置和资产摘要。修改任意影响发布的内容形成新计划。重跑已完成任务返回已有结果；明确要求再发一份时创建新任务。

执行计划固定内容与资产摘要、驱动及渲染版本，运行前核对输入变化。自动更新只在任务边界生效，不能在同一任务内混用适配器版本；恢复任务遇到版本不兼容时先迁移或保留原版本。

## CLI 与自然语言入口

下列命令用于说明设计目标，当前尚不可执行：

```bash
wm platform list --json
wm platform capabilities wechat --account main --json
wm auth login wechat --account main
wm auth login xiaohongshu --account main
wm auth status --json
wm article preview article.md --platform wechat --json
wm draft create article.md --platform wechat --account main --json
wm article publish article.md --to juejin:main,wechat:main --json
wm job get JOB_ID --json
wm job resume JOB_ID --json
wm schema article publish --json
```

发布输入可以是源文件或已有草稿引用，两者在命令契约中明确区分。默认不把群发包含在公众号发布动作中。跨平台不支持的目标在准备阶段给出具体原因，不能静默跳过。

自然语言示例为“把这篇 Markdown 排版后保存到我的公众号草稿箱”和“将确认过的文章发到掘金和公众号，告诉我每个平台的结果”。AI 负责理解内容意图并调用 CLI；实际副作用只发生在确定的处理器中。用户已明确授权的发布不重复审批，账号或内容不明确时再补足信息。

额外能力继续遵守同一账号、锁、回执和错误契约。平台特有能力可通过 wm wechat 或 wm xiaohongshu 的命名空间暴露，公共任务服务不感知 DOM 或私有协议。

## 对基线的必要调整

| 当前机制 | 存在的耦合 | 改造位置 |
| --- | --- | --- |
| runtime/session.ts | Cookie 类型、掘金域名、HTTP 验证、登录和写锁在同一模块 | runtime 保留账号存储与锁；掘金认证迁到 platform/juejin/auth |
| content/markdown.ts | 导入掘金 imagex.validateImage，公共图片校验受掘金约束 | content 只建立资产清单；平台上传规则归各自 adapter |
| cli/context.ts | 直接构造 JuejinClient、ImageUploader、WritingService | 在 composition root 通过注册表装配平台和驱动 |
| services/writing-service.ts | 草稿、专栏、文章、签到与抽奖共用掘金模型 | 公共任务服务负责阶段和回执；掘金写作与增长功能留在平台扩展 |
| publishDirectory | 仅支持单一掘金专栏与 draft_id/article_id | 批处理复用通用任务，每个平台账号分别保存进度 |
| runtime/journal.ts | failed_or_unknown 合并明确失败与未知结果 | 区分 rejected、unknown、submitted 和 confirmed，关联任务与阶段 |
| 默认目录和发行流程 | 包名、环境变量、Skill、站点与 CI 都指向 juejin-cli | 统一改为 wemedia-cli，隔离配置及发布目标；保留来源和许可 |

现有 SDK 与测试可用于验证掘金迁移，但新项目不必保持 juejin-cli 的命令兼容。保留可靠的机制与行为契约，删除已被新职责替代的耦合路径。

## 实现顺序与验收

第一阶段建立新包身份、能力注册表、账号管理、任务与回执、schema、平台渲染；将掘金迁移为首个 adapter，用已有测试验证公共层没有掘金协议依赖。

第二阶段接入小红书受管理引擎和微信公众号浏览器草稿。用户只执行登录，工具完成其余配置。文颜作为固定版本依赖接入，先验收纯本地渲染，再在获准的账号和内容上验证上传及草稿回读。

第三阶段分别验收正式发布、验证中断恢复、结果查询及跨平台部分失败。平台尚未通过的能力在 capabilities 中保持不可用，不能通过“运行未报错”推定可对外使用。

第四阶段接入新平台，例如知乎或 CSDN。验收标准是新增平台目录、注册项和对应测试即可接入，既有任务调度和 CLI 公共流程无需增加平台分支。有真实独立发布需求时再引入版本化外部插件契约。

公共层测试重点覆盖账号隔离、并发、已完成阶段跳过、unknown 不重放、多平台部分失败和能力拒绝。浏览器测试覆盖真实故障机制，例如失去焦点、图片未上传、封面弹窗、跳转到登录页、扫码超时及保存回执缺失。真实账号验收单独记录，不与离线通过混淆。
