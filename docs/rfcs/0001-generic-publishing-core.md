# wm 通用发布核心设计

状态：设计方案。目标版本：0.2。基线：main 的 77b1636。本文定义尚待实现的核心契约；当前能力以实际命令 schema 和验收记录为准。

wm 以一个 CLI 和一个同名 Skill 服务所有平台。用户完成登录后，AI 使用业务能力管理内容，平台驱动负责后台操作。核心只理解内容、账号、能力、计划、操作记录和执行状态；平台名称、私有字段、接口和选择器均由适配器持有。

## 目标与范围

0.2 首先解决内容冻结、账号身份、跨任务去重、写入回查和验证恢复。0.3 增加远端内容管理与更新，0.4 用第四个平台验证扩展边界。批量和定时发布复用已经验收的执行器。

新设计直接替换旧契约。旧命令别名、旧 Skill 名称、旧任务 schema 读取器、接口转接层和自动迁移不进入核心。历史文件保留原件；存在结果未确认的旧写入时，应先使用产生该任务的版本核对远端结果，再开始新的发布。

本文不增加平台 UI 操作要求。平台强制的扫码或身份验证仍由用户完成；浏览器准备、页面导航、表单和结果读取由驱动处理。

## 通用化约束

1. core、content 的通用模块、services 和 runtime 不出现具体平台 ID、平台字段或选择器。CLI 仅在内置注册表装配处列出适配器。
2. PlatformId、CapabilityId、ResourceKind、ArtifactKind 使用注册标识，不以掘金、小红书、公众号或现有内容格式组成封闭枚举。
3. 公共执行器不判断“某平台先存草稿”“某平台必须上传封面”。步骤及依赖来自驱动编译出的工作流。
4. 平台输入、约束、输出及账号前置条件由能力定义拥有。公共层不解释不透明的平台 payload。
5. 新平台通过一个目录、一个注册项和对应契约测试接入；公共任务服务无需修改。
6. 安装包只分发 skills/wm/SKILL.md 一个 Skill 入口。平台指导作为其按需引用的参考内容，不再分发平台 Skill 或绘图 Skill。
7. 没有实现的能力不注册。已实现、账号可用、线上验收通过分别表达，不能互相替代。

通用化不要求所有平台具备相同功能。草稿、群发、视频、合集等是可选能力；一个平台缺少某项能力时返回不支持，不伪造替代行为。

建议职责位置：

| 位置 | 职责 |
| --- | --- |
| core/ | 领域对象、能力及驱动契约、状态归约规则 |
| content/ | 导入器、资产快照、通用产物；Markdown 是一个导入器 |
| services/planning | 目标绑定、内容准备、计划冻结 |
| services/execution | 步骤执行、操作去重、回查与恢复 |
| services/publications | 远端引用、修订关联及更新冲突 |
| runtime/ | 存储、锁、会话、浏览器与引擎生命周期 |
| platform/<id>/ | 平台 schema、约束、渲染、驱动、观察结果归一化 |
| cli/ | 参数、展示、公共快捷命令、通用能力调用 |
| skills/wm/ | 自然语言路由、命令发现、结果处理及必要参考 |

平台实现不导入 CLI。通用内容导入器不导入平台渲染器。渲染器由平台注册，执行器只接收产物和引用。

## 领域对象与身份

| 对象 | 稳定字段与职责 |
| --- | --- |
| AccountBinding | bindingId、platformId、平台返回的 accountId；别名只是可修改的索引 |
| ContentRevision | revisionId、原始内容产物、通用元数据、资产清单；创建后不可变 |
| PreparedVariant | variantId、平台产物、语义配置摘要、渲染器记录；不强制存在 title 或 HTML |
| PublishPlan | planId、目标能力、账号身份、修订及平台版本内容、工作流与驱动快照 |
| Job | jobId、planId、目标执行摘要；多次继续执行共享同一组操作记录 |
| OperationRecord | operationId、语义去重键、步骤状态、实际结果、远端引用和证据；负责写入事实 |
| Publication | 本地 publicationId、所属账号、远端引用集合、来源修订、最新远端观察 |

所有远端 ID 均保存为字符串。ResourceRef 包含 platformId、accountId、kind、id，以及协议要求的资源定位字段。kind 和定位字段由平台 schema 定义；同一远端容器中的不同子内容不能仅凭容器 ID 判为相同。

草稿引用、提交单号和公开文章引用可以属于同一 Publication，但不能互换。公开链接仅保存可分享地址，不保存带账号 Token 的后台编辑 URL。

计划绑定真实 accountId。执行时重新验证当前会话身份，即使别名后来指向另一账号，也不能改写旧计划的目的地。同一平台账号的多个别名共享账号锁和操作去重作用域。

新版本采用新的账号绑定布局。用户通过 wm auth login 建立绑定，不实现旧目录扫描、自动重命名或凭据搬迁。

## 内容修订与平台产物

读取内容、解析输入、建立快照、应用平台配置、生成平台产物、校验，然后冻结计划。所有目标完成准备后，才能开始平台写入。

内容产物记录 MIME 类型、摘要、大小和存储引用，支持文本或二进制。公共核心不限定 markdown、html、image-text 三种格式。输入导入器处理 Markdown 等来源；平台渲染器决定实际接受的内容。

本地资产以内容摘要存储，执行时使用快照路径，不再读取原文件。图片顺序、出现位置及封面用途属于平台内容语义，必须进入平台产物或配置摘要。共享资产模块只处理存储和完整性，各平台分别处理尺寸、格式、数量和大小限制。

0.2 对需要上传的素材使用本地快照。允许外部引用的能力必须明确声明 external 策略，只冻结 URL，不宣称冻结远端字节；不在本阶段增加自动抓取远程资源的通用服务。

源文件绝对路径、快照所在目录和导入时间只是来源信息，不参与语义去重。原始正文及声明的元数据变化形成新修订。平台输出中的临时文件路径必须用稳定的资产引用替代后再计算摘要。

字段优先级延续命令参数、目标平台配置、公共元数据。平台 payload 在其拥有的输入 schema 边界校验一次；成功的内部类型不逐层重复检查。

## 平台与能力定义

一个 PlatformDefinition 提供平台 ID、能力定义、内容准备器和驱动集合。能力定义包含：

| 字段 | 含义 |
| --- | --- |
| id | 稳定的业务能力标识，可注册公共能力或平台扩展 |
| inputSchema 与 outputSchema | 输入输出契约，类型和运行时校验使用同一来源 |
| effect | read 或 remote-write，决定是否经过持久化操作记录 |
| constraints | 当前输入的格式、字段与限制 |
| drivers | 实现此能力的驱动及工作流编译器 |
| probe | 账号及运行环境的能力探测 |
| acceptance | 与驱动版本关联的离线、线上读取、线上写入验收证据 |

content.publish、draft.create、draft.update、resource.get、resource.list 是可复用的业务语义，不是要求每个平台实现的接口全集。平台扩展采用命名空间注册，公共执行器处理方式相同。

能力定义拥有 payload schema；Commander 定义拥有命令行语法。wm schema 从这两类实际定义生成说明，不再单独维护另一套平台字段清单。Skill 通过 schema 发现当前能力。

账号探测返回 available、unavailable 或 unknown，并说明原因及观察时间。静态处理器存在不能证明账号拥有发表权限；探测未知也不能伪称无权限。执行前读取实际前置状态，在具有明确拒绝证据时停止。

## 驱动工作流

驱动把一次业务请求编译成有限步骤与依赖。步骤引用已注册的处理器和版本，输入来自冻结产物、明确常量或前置步骤输出。不引入任意脚本、表达式语言或远程代码执行。

工作流可以直接提交内容，也可以上传素材、创建草稿后再发表。公共执行器只负责依赖顺序、锁、回执、错误和回查；不补插任何平台专有步骤。步骤成功的输出需要足以支持后续恢复。

驱动版本和工作流版本固定在计划内。恢复时不兼容则返回明确的版本错误，不自动重编译或换另一驱动重发。单纯 CLI 版本升级不构成发布副本，也不改变已保存的远端事实。

0.2 先顺序执行目标及其依赖，不建设并行任务调度器。浏览器会话在一次目标执行中复用，避免验证账号和执行写入分别启动两次浏览器。

## 跨任务去重与资产复用

整批任务指纹只负责找到同一计划；防止重复远端写入必须落实到每个目标及具体操作。

语义去重键包含平台、真实账号、能力、内容修订、平台产物摘要、影响远端行为的配置、被修改的资源引用，以及用户明确要求新副本时产生的 copyNonce。集合字段先按契约规范化，再稳定序列化并计算摘要。

CLI 版本、源文件位置、账号别名、目标排列顺序、运行时间和探测时间不进入语义键。驱动或渲染器升级是否改变内容，以实际产物和行为语义为准，版本记录仍用于兼容性检查。

例如先向 A、B 发布，再向 A、C 发布，两份计划中的 A 应引用同一操作记录。跨进程使用账号锁与操作锁保证查重和创建原子完成。明确要求新副本时，copyNonce 传播到依赖的创建与发表步骤，避免再次使用旧草稿。

上传缓存按平台、真实账号、能力或用途、资产摘要和上传协议版本隔离。缓存记录平台有效期；无有效依据时由驱动核对或重新上传，不能跨账号使用素材标识。

## 写入状态与证据

步骤使用 ready、running、waiting_for_verification、succeeded、rejected、unknown。rejected 表示具有未产生该次业务效果的明确证据；网络异常和进程退出不作此推断。

执行状态与远端状态分别记录。执行器完成一次提交，远端仍可能在 submitted 或 processing；只有相应证据才能记为 published。平台的原始状态保存在受控字段中，由适配器映射。

| 事件 | 处理 |
| --- | --- |
| 写入即将发出 | 先持久化 running，再调用远端处理器 |
| 远端返回确定成功 | 同一个 OperationRecord 原子保存步骤输出、远端引用和证据 |
| 已保存回执后附加事件日志失败 | 保留成功事实，报告日志问题，不重新发送 |
| 明确业务拒绝 | 保存 rejected；仅显式 resume 且符合该能力重试条件时再执行 |
| 写入超时、进程退出或本地回执未完成 | 保存或恢复为 unknown，先只读回查 |
| 后续审核拒绝或远端删除 | 增加新观察；保留先前提交证据，更新当前远端状态 |

OperationRecord 是写入事实的唯一权威。Job 摘要、Publication 索引和 events.jsonl 均为可重建视图。索引写失败时不能丢失已经保存的远端引用；恢复应从权威记录重建。事件日志不是第二套事务系统。

## 回查与恢复规则

驱动对某一步返回 effect_confirmed、not_applied 或 indeterminate，并携带可定位到该操作的证据。列表暂时未出现、标题相同或离开发布页，都不足以单独证明是否执行成功。

effect_confirmed 可以完成对应步骤，并使后续尚未执行的步骤继续。not_applied 必须来自协议或范围完整、身份明确且不存在最终一致性歧义的证据，才允许该步骤再次执行。其余情况保留 unknown。

已确认保存的草稿只证明草稿存在，不能证明一次发表未发生。回查发表必须使用该平台可用的文章或提交引用。没有稳定关联依据时保留未知，不从标题推测归属。

refresh 逐目标读取并记录观察。某一目标读取失败不阻止其他目标；读取失败也不覆盖已有成功证据。查询时间和证据新鲜度独立呈现，避免把历史成功误读成“刚刚在线确认”。

resume 按步骤事实决策，跳过成功步骤；遇到未确认写入先回查。结果仍未知时退出并给出具体原因，不通过新建任务绕过去重。

## 用户验证与会话生命周期

驱动报告验证类型、对应阶段、恢复策略和不含凭据的 verificationId。公共 runtime 管理会话生命周期，不解释平台页面。

同一 CLI 进程等待扫码时保留浏览器和账号锁。验证完成后继续当前步骤或先回查，由驱动根据提交是否可能发生决定。超时后先保存必要引用与待验证状态，再关闭上下文和释放锁。

跨进程恢复通过驱动提供的资源引用重建验证入口。需要重新登录时只打开登录流程；不能将带 Token 的编辑 URL、Cookie 或验证码写入任务记录。无法安全重建提交阶段时停在 unknown，不重新点击发表。

用户只操作登录或平台强制验证，常规后台页面仍由 CLI 完成。0.2 不引入常驻后台服务；真正需要跨进程持续等待或定时运行时，再为同一执行器增加宿主。

## 存储与并发

先沿用本地文件存储，避免为本阶段引入数据库运行时。不可变内容和计划使用按摘要存储的文件，操作记录使用私有权限和原子替换。

~~~text
wemedia-home/
  accounts/<bindingId>/account.json
  accounts/<bindingId>/browser-profile/
  aliases.json
  objects/<digest>
  revisions/<revisionId>.json
  variants/<variantId>.json
  plans/<planId>.json
  jobs/<jobId>/job.json
  operations/<operationId>.json
  indexes/publications/
~~~

索引可以删除后重建，不作为去重正确性的前提。锁顺序统一为 job、account、operation；每次只持有一个目标账号，避免跨平台锁循环。只读操作若使用同一个浏览器 Profile，也参与账号会话锁。

遇到锁竞争返回 BUSY，不作为平台业务拒绝。崩溃锁保留所有者信息，恢复工具检查实际进程和工作目录后才能清理；不依据一个任意过期时间自动删除仍在运行的锁。

文件系统事务边界和索引重建已经足够支撑首期单机顺序执行。出现多机协调、持续队列或明确的事务性能需求时，再选择数据库。

## CLI 与单一 Skill

wm 是唯一可执行命令和 Skill 名称。平台差异通过能力 schema 和参考文档发现，不增加独立平台 Skill。

以下为目标命令，具体参数以实现后的 schema 为准：

~~~bash
wm platform list --json
wm platform capabilities PLATFORM --account main --json
wm auth login PLATFORM --account main
wm article plan article.md --to PLATFORM:main --intent publish --json
wm job get JOB_ID --json
wm job resume JOB_ID --json
wm job refresh JOB_ID --json
wm draft update RESOURCE_REF --file article.md --json
wm platform exec PLATFORM CAPABILITY --account main --input input.json --json
~~~

article、draft 命令是常见业务能力的快捷入口；platform exec 调用已注册能力，使用相同账号、输入校验、工作流与回执。它不接受任意 URL、脚本或浏览器选择器。新增平台扩展无需修改公共命令树。

preview 和 dry-run 保持本地、无平台写入。plan 生成确定的可执行计划，要求已有本地账号绑定；执行时再核对在线身份。不存在绑定时提示登录，不在计划中留下可被之后重绑定的空账号。

Skill 负责理解目标、准备平台版本内容、读取 schema、调用命令和解释结果。平台填写与错误恢复由 CLI 实现。用户授权存草稿时止于草稿；明确给出内容、账号和发布目标后不增加一轮机械确认。

JSON 成功位于 stdout，错误位于 stderr，沿用现有退出码分类。错误增加 reason、job_id、stage、required_action 和结构化 next_action；调用参数用数组表示，不拼装可执行 shell 字符串。

~~~json
{
  "ok": false,
  "error": {
    "code": "VERIFICATION",
    "reason": "identity_verification_required",
    "job_id": "example-job",
    "stage": "content.publish",
    "required_action": "scan_in_browser",
    "next_action": { "command": "wm", "args": ["job", "resume", "example-job"] }
  }
}
~~~

上例中的任务 ID 是占位符。成功输出分别报告各目标的执行与远端状态，不用一个布尔值掩盖部分完成。

## 平台接入与开源复用

接入者实现定义、内容准备、驱动处理器、账号验证和观察归一化，并补齐契约测试。真实后台路径保留在平台目录，不复制进公共服务。

优先复用已验证且许可明确的底层库或流程，记录来源提交、修改范围与许可证。已经移植的浏览器流程继续在对应驱动维护，不为“统一”而再套一层外部 MCP 服务。只有实际需要独立引擎时，才由 runtime 管理安装、版本、进程和健康检查。

外部插件包在出现独立发布需求后再设计。首期内置适配器与未来外部包遵守相同能力边界，平台注册不依赖插件市场。

## 验收与交付

通用契约测试至少包含一个不带草稿能力的平台、一个只接受二进制产物的平台，以及自定义资源种类和能力。它们必须由同一执行器运行，不能在核心添加名称或格式分支。

关键验证包括目标部分重叠的跨任务去重、别名变化、原文件移走、上传缓存作用域、回执已保存但索引失败、未知写入回查、验证超时、终态观察与跨平台部分失败。

真实写入验收使用明确指定的内容和目标，分别记录草稿保存、提交受理、最终展示及验证恢复。本设计任务只提交方案和入口收敛，不创建真实文章。
